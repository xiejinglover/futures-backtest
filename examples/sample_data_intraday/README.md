# 日内样例数据

一个品种 `RB`、两个合约 `RB2405` / `RB2410`、5 个交易日（2024-04-08 ~ 2024-04-12），
**15 分钟** bar，每交易日 23 根:夜盘 8 根 + 日盘 15 根。合计 230 行。

选 15m 而不是 5m 只是为了文件小到能直接读;引擎不重采样,`bar_freq` 必须与数据实际
周期一致,换成 5m 数据把 `bar_freq` 改掉即可。

## 夜盘归属

这份数据的重点之一是**夜盘 bar 的 `trading_day` 按交易所口径归属次日**:

| bar 的 `datetime` | `trading_day` |
|---|---|
| 2024-04-05（周五）21:15 ~ 23:00 | **2024-04-08**（周一） |
| 2024-04-08 21:15 ~ 23:00 | 2024-04-09 |

所以每个交易日的**首根 bar 是前一晚 21:15**,而不是当日 09:15。引擎把"今仓滚入昨仓"
挂在首根 bar、把结算挂在末根 bar,两者都只看 `trading_day`,标错就全错。区间过滤也走
`trading_day`,所以 04-05 晚上的 bar 会被 `start: 2024-04-08` 正确包含。

## 换月

主力在 **2024-04-10** 由 `RB2405` 切到 `RB2410`,`dominant_lag: 1` 使框架在
**2024-04-11** 才真正移仓。两个合约有约 60 点价差,换月成本本应可见——但日内策略
每天收盘前平光,换月时手上没仓位,所以 `rolls.csv` 是空的而 `events.csv` 里仍有一条
`ROLL`。这是真实结论:不留隔夜的策略不付移仓成本。

## 其它刻意安排

- 结算价 = 当日最后一根 bar 收盘价 - 2,用来验证日终盯市走结算价而非收盘价;
- `close_today_fee_rate` 是普通费率的 **10 倍**(上期所螺纹钢平今就是这样),日内
  策略的手续费会明显盖过毛利,这是日内回测最容易被忽略的一项;
- 涨跌停价设为基准价的 ±6%,区间内不会触发,只是让字段不为空。

价格是固定种子的随机游走,不代表任何真实市场收益。
